CLAUDE.md Anatomy

CARD 2 / 6
Section-by-Section Breakdown
01 Role / Identity One sentence. Who Claude is in this project. Stack + domain + seniority level. Example: "You are a senior TypeScript engineer on a Next.js 14 App Router project."
02 Non-Negotiables Hard rules prefixed NEVER / ALWAYS. 5-8 max. These are prohibition lines, not suggestions. Claude treats violations as hard failures. Put your most common mistakes here.
03 Project Structure Directory tree (3-4 levels). Mark which dirs are read-only, which are write targets. Include what goes where. Prevents writes to wrong locations.
04 Key Patterns The 3-5 idioms used in this codebase. Error handling style, async pattern, state management. Include a mini code example per pattern. Link to files that demonstrate each.
05 Commands Exact shell commands for: build, test, lint, type-check, run-dev. No generic npm test — use your actual scripts. These get executed verbatim.
06 Testing Requirements What constitutes a complete change: unit tests, integration tests, coverage thresholds, what to mock vs use real. Include the command to verify tests pass before marking done.
07 External Tools / APIs List of tools available: databases, APIs, CLIs. Where credentials live. Preferred auth patterns. Rate limits or cost concerns that affect approach.
08 Workflow The sequence: read → plan → implement → test → verify. Include your completion criteria. "Never declare done without running verify-completion.py." This is the meta-loop.
Good vs Bad Examples
GOOD
You are a senior Rust engineer specializing in async tokio services and zero-copy parsing. Specific role with domain expertise signaled
NEVER use .unwrap() in production code paths. Use ? or map_err. Concrete prohibition with an alternative
Build: cargo build --release
Test: cargo test --workspace
Lint: cargo clippy -- -D warnings Exact, runnable commands
See src/db/connection.rs for the connection pool pattern. All DB access goes through this module. Points to a real file as the canonical example
BAD
You are an expert programmer who writes good code. No domain, no stack, no signal — ignored by Claude
Write safe code and handle errors properly. Vague guidance with no enforcement mechanism
Run tests before committing. No actual command — Claude cannot verify this
Follow the existing patterns in the codebase. Requires Claude to infer patterns from nothing

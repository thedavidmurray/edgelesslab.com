20:T100f,<h1>16 Agents, Not 1000: What Claude's Dynamic Workflows Actually Mean</h1>
<p>Claude Opus 4.8 shipped "dynamic workflows" — Claude writes its own orchestration script, fans the task out to parallel sub-agents, and runs verifier agents until the output converges.</p>
<p>The marketing says "hundreds of parallel agents." The docs say something different. Here's the reality.</p>
<p>---</p>
<h2 id="what-it-actually-does">What It Actually Does</h2>
<p>Two triggers:</p>
<ol><li><strong>Type the word "workflow"</strong> in your prompt: Claude shows the orchestration plan before running</li><li><strong>Flip on Ultracode</strong>: Maxes effort and lets Claude auto-decide when a task warrants a full workflow</li></ol>
<p>The workflow is adversarial and convergent:</p>
<ul><li>Claude decomposes the task into stages</li><li>Fans parts out to parallel sub-agents</li><li>Spins up separate verifier agents</li><li>Gates output so nothing reaches you until checked</li><li>If interrupted, resumes where it left off</li><li>Can span hours to days</li></ul>
<p>This is the productized version of what we've been doing manually: Wave A→E with adversarial verification and snapshot/rollback.</p>
<p>---</p>
<h2 id="the-real-concurrency-limit">The Real Concurrency Limit</h2>
<p><strong>Only 16 agents run concurrently.</strong> Up to 1,000 total across a job's lifetime, but never more than 16 live at once.</p>
<p>The "hundreds in parallel" framing is marketing. The reality is a hard ceiling that, if pushed, triggers rate limits.</p>
<p>This is still powerful. 16 agents with verification is a 10x force multiplier over a single agent. But it's not infinite.</p>
<p>---</p>
<h2 id="the-cost-trap">The Cost Trap</h2>
<p>Anthropic explicitly warns: "uses meaningfully more than a normal session."</p>
<p>Critics call it "the fastest way to speedrun your weekly usage limit."</p>
<p>The rule: <strong>not for small jobs.</strong> Scope it to genuinely large work — migrations, audits, multi-file refactors — or you're just lighting money on fire.</p>
<p>But the counter-argument is strong: a migration that would cost a 3-person team 3 months can collapse to ~a week for a few hundred dollars in tokens. "One of the best trades in all of software."</p>
<p>---</p>
<h2 id="real-proof-points">Real Proof Points</h2>
<h3>The Bun Port</h3>
<p>Jarred Sumner ported the Bun engine from Zig to Rust:</p>
<ul><li>~750,000 lines of code</li><li>99.8% of the old test suite passing</li><li>11-day run</li><li>Two reviewer agents hammered every single file until the build passed</li></ul>
<h3>The A/B Flag Sweep</h3>
<p>Anthropic engineer Kat Woo cleared hundreds of A/B test flags in under 10 minutes — work that "rots in a backlog for over a year."</p>
<p>---</p>
<h2 id="how-to-use-it">How to Use It</h2>
<ol><li><strong>Start small</strong>: Test the "workflow" keyword on a real codebase audit. Capture the orchestration plan it proposes.</li><li><strong>Define "workflow-worthy"</strong>: Lines touched / files / estimated token burn. Only trigger for genuinely large jobs.</li><li><strong>Add guardrails</strong>: Token-burn watch + usage limit before any multi-day run.</li><li><strong>Pair with auto mode</strong>: 100 agents wanting minor changes = manual approval fatigue. Auto mode assesses permissions and only escalates on critical actions.</li><li><strong>Benchmark against your manual process</strong>: Compare token cost vs. quality vs. time.</li></ol>
<p>---</p>
<h2 id="the-verdict">The Verdict</h2>
<p>Dynamic workflows are a real 10x multiplier for the right tasks. But they're not magic. The concurrency limit is real. The cost is real. The value is in the verification layer — the adversarial convergence that catches errors before they ship.</p>
<p>The pattern is: <strong>orchestration + verification + resumption</strong>. Claude productized it. You can build it yourself. The question is whether the native version is worth the token tax.</p>

# edgelesslab.com — Ox Fan-Out Audit

**Date:** 2026-08-23
**Auditor model:** `stealth/ox-alpha` (Ox, free promo) via OpenRouter — frontier coder, 1M context
**Verification:** Adversarial Ox refute pass + Claude code-level confirmation of top findings
**Cost:** $0 (every Ox call returned `cost: 0`)

---

## Executive summary

The site's real auditable surface is small (~273 source files under `src/`, `content/`,
`blog/`, `docs/`, `workers/`, `scripts/`, config — the 78k-file repo total is ~99% build
output and static assets). A concurrent Ox fan-out over an 8-dimension × subsystem matrix
produced 88 raw findings; after de-duplication (67) and an adversarial Ox "refute-this" pass
that **discarded 43%** as weak or false, **18 findings were confirmed** and 20 remain
"worth a look." The five highest-impact were then confirmed by Claude directly against the
source.

**The single most important finding is a root cause, not a symptom:**

> **`next.config.ts` sets `typescript: { ignoreBuildErrors: true }`** — TypeScript errors do
> not fail `next build`. The type system is switched off as a correctness gate. This is what
> allows a real `ReferenceError` (undefined `products` in a lazy-loaded component) to exist
> undetected, and it means *any* future type error can ship silently.

The richest concrete cluster is **`workers/ingest/worker.js`** (the PostHog ingest Worker):
8 confirmed issues spanning correctness, security, performance, and billing integrity.

---

## Method (how this was produced)

1. **Chunk** — grouped source into subsystems; each subsystem concatenated into ≤200k-char
   chunks (Ox's 1M window makes fat, coherent chunks better than thousands of keyhole reads).
2. **Find (fan-out)** — 54 concurrent Ox passes over an 8-dimension matrix
   (correctness, security, SEO, accessibility, performance, content, dependencies, deploy),
   each returning structured JSON findings.
3. **Crawl** — all 60 sitemap URLs fetched live (all HTTP 200, no dead top-level pages),
   each page audited by Ox for live SEO/a11y.
4. **Refute (adversarial)** — every unique finding re-sent to Ox as a skeptic instructed to
   refute vague/false positives. **29/67 refuted, 20 uncertain, 18 confirmed.**
5. **Verify (Claude)** — top findings confirmed against the actual code; this layer caught
   that Ox's "critical" was a symptom of the `ignoreBuildErrors` root cause.

All Ox calls rate-limited to 110/min (under the 120/min ceiling). Harness:
`scratchpad/oxaudit/ox.py` (stdlib-only, idempotent, re-runnable per phase).

**Honesty note:** the live-page audits were low-signal — 18 of 21 were refuted (they were
based on trimmed HTML snippets). Trust the repo-source findings; treat live-crawl output as
a weak secondary signal.

## Confirmed findings — priority order

### P0 — Build & type safety (root cause)

**1. `next.config.ts` — `typescript.ignoreBuildErrors: true` disables the type gate.**
The build (`next build`) does not fail on TypeScript errors, and `package.json`'s `build`
script runs no separate `tsc` typecheck. Consequence: type errors ship. This is the enabling
condition for finding #2 and any future type regression.
*Fix:* remove `ignoreBuildErrors` (or set a CI `tsc --noEmit` gate that blocks deploy). Fix
the errors it currently hides before flipping it.

**2. `src/components/home-client.tsx` — `ProductHighlight` uses undefined `products`.**
Lines ~536–539 call `products.filter/.find/.length`, but `products` is never imported or
declared in the file. Ox rated this *critical*; Claude verification refined it: this
`ProductHighlight` is an **orphaned duplicate** — the *live* one is
`src/components/product-highlight.tsx` (imported by `cta-section.tsx`). However,
`home-client.tsx` **is** lazy-loaded via `import("@/components/home-client")` in
`project-showcase-section.tsx` and `tech-showcase-section.tsx`, so the dead export is a
latent `ReferenceError` in shipped chunks, masked only by #1.
*Fix:* delete the dead `ProductHighlight` from `home-client.tsx` (or import the catalog); then
turn #1 back on so this class of bug can't recur.

### P1 — `workers/ingest/worker.js` (PostHog ingest Worker) — 8 confirmed

| # | Sev | Issue | Fix |
|---|-----|-------|-----|
| 3 | high | Unhandled rejections: malformed JSON body and PostHog `fetch` failures throw bare 500s (CF 1101) instead of 400/502, and without CORS headers | wrap `request.json()` and the upstream `fetch` in try/catch, return controlled 4xx/5xx |
| 4 | med | Unvalidated payload spread injects PostHog reserved keys (`timestamp`, `$set`, `$set_once`, `lib`) — lets a forged request backdate/mutate events | destructure reserved keys out before `...safeProps` |
| 5 | med | `ALLOWED_ORIGINS="*"` never matches (exact-string `includes`), silently falls back to hardcoded origin → CORS mismatch | add explicit wildcard branch before exact match |
| 6 | med | Handler `await`s PostHog `/capture/` before responding — every beacon pays full third-party RTT | move POST behind `ctx.waitUntil(...)` |
| 7 | low | `/health` and 405 replies omit CORS headers (all other branches include them) | pass `corsHeaders(request, env)` in both |
| 8 | low | Dynamic `Access-Control-Allow-Origin` without `Vary: Origin` — cache-poisoning risk if ever cached | add `Vary: Origin` |
| 9 | low | `/health` has no `Cache-Control` → stale uptime signals possible | return `Cache-Control: no-store` |
| 10 | low/deploy | `crypto.randomUUID()` fallback mints a **new PostHog person per event** lacking an ID → inflates MTUs (billing) + breaks funnels | require `anonymous_id` (400 if absent); persist it client-side |

### P1 — Correctness / static-export mismatches

**11. `src/lib/now-data.ts:60` (high, performance) — relative-URL fetch fails at prerender.**
`fetch('/data/ship_log.json')` / `content_wall.json` use relative URLs. Node's build-time
fetch can't resolve them → throws `Failed to parse URL` → a bare catch swallows it → **empty
"now" data is baked into the static HTML**. *Fix:* move the JSON into `src/data/` and
`import` it directly so values inline at build.

**12. `src/app/feed.xml/route.ts:54` (med, correctness) — response headers silently dropped.**
`feed.xml`, `humans.txt`, `llms.txt` set `Content-Type`/`Cache-Control` in handler headers,
but under `output: 'export'` + `force-static` these are prerendered to plain files and the
headers are discarded. *Fix:* move caching/content-type to the host layer (`_headers` on the
actual host — see #17).

### P1 — Security / build integrity

**13. `src/components/blog-article.tsx:148` (med, security) — unsanitized `dangerouslySetInnerHTML`.**
Renders the whole post body via `dangerouslySetInnerHTML={{__html: html}}` with no sanitize
step. The blog slug route (`src/app/blog/[slug]/page.tsx:68`) runs the content through a
custom `renderMarkdown()` (defined at :330) that passes raw HTML through. Content is currently
author-controlled (repo markdown), so this is latent — but any CMS/RSS-sourced content becomes
a stored-XSS vector. *Fix:* sanitize once in the markdown pipeline with `rehype-sanitize`
(allowlist).

**14. `scripts/bundle-enforce.ts:101` (med, security) — integrity checks are advisory by default.**
Exit code is only set under `--strict`. In a default run a failed `artifact_maps_clean` check
(sourcemaps shipped in `out/` = full source disclosure) logs `[FAIL]` but the build/deploy
still succeeds. *Fix:* fail by default; make `--warn` the opt-in, and confirm CI passes `--strict`.

**15. `eslint.config.mjs:31` (low, security) — `react/no-unescaped-entities` disabled repo-wide.**
Not directly exploitable (React escapes JSX text), but removes a guardrail. *Fix:* scope the
override narrowly instead of a global off.

### P2 — SEO / content (blog)

- **16 (high):** `blog/agentic-engineering-week`, `multi-agent-orchestration-week`,
  `verification-chain-crisis` `.mdx` files have **no frontmatter** (no title/description/date)
  → no per-page `<title>`, meta description, canonical, OG/Twitter, Article JSON-LD, or sitemap
  lastmod. Also `blog/stanford-genai-worth-2026.md` is a bare `.md` outside a route dir.
- **9/16 (med):** **No Open Graph / Twitter Card metadata on any post** — social shares render
  as bare URLs with no preview, on a blog whose distribution model *is* social sharing.
- **17 (low):** `blog/glm-5-2-eval-report/index.mdx` has title+date but no `description`
  (and is the only post using `index.mdx` vs `page.mdx`).
- **14 (low, performance):** ~25k vendored JS files under `public/` (marimo, total-serialism,
  scoop-scout, creative-demos, pen-plotter, prompt-engine) are copied into `out/` on every
  build — slow deploys, large artifact. *Fix:* prune unreferenced files; lazy-load on mount;
  consider a versioned CDN path outside the Next build.

### Deploy topology (flagged, verify against production)

**18. `_headers` / `_redirects` are Cloudflare-Pages format.** If production is served from
**GitHub Pages** (per project deployment notes: `edgeless-ai/edgelesslab.com`, `cname:
edgelesslab.com`), these files are **inert** — Cloudflare header/redirect rules do nothing on
GitHub Pages. This also means the fixes in #12/#8/#9 that rely on `_headers` won't take effect
there. *Action:* confirm the actual host and, if GitHub Pages, move caching/security headers to
whatever the host supports (or a Cloudflare proxy in front).
